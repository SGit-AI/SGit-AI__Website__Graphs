# operators — the little words that flip meaning

**T5 · optional · reads `stream` · writes `stream`**

Born from the founder's live experiment (brief 33): "meaning without connectivity"
answered exactly like "meaning through connectivity", because *without* was padding.
This engine reads the little words: each entry in its word table either NEGATES or
CONTRASTS. A negating word marks the NEXT known, non-padding, non-operator token as
negated; the mark withdraws that word from positive binding downstream while keeping it
visible for converge's contradiction check — negating something this universe asserts is
said out loud, never silently resolved.

## the transformation

```
  stream ──────────────────────────────────────────────────────────►

   meaning   without   connectivity
      │         │           │
      │     in table?       │
      │      negates ─── marks NEXT known non-padding token
      │         │           │
      ▼         ▼           ▼
   passes    class =     negated = true
   through   operator       │
                            ├─► bind: withdrawn from `present`
                            └─► converge: "the prompt negates
                                'connectivity', but this universe
                                holds … — the query contradicts
                                the world."
```

## official data

`data.json` carries the word table itself — **standard** across every document:
`without / not / no / never → negates`, `versus / vs → contrasts`. Extending the
engine's reach is editing this table.

## tuning notes

Contrast is recognised and recorded but not yet acted on downstream — the honest current
state. Open judgement (brief 33's note): should a negated term also DEMOTE concepts that
merely mention it, or only withdraw it from positive evidence? Today it is the latter.
Scope is one token; "not very connected" negating a phrase is future grammar work
(brief 34's "eventually, grammar rules").
